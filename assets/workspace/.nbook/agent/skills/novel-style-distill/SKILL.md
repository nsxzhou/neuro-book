# novel-style-distill：文风蒸馏（熔铸法）

读取 writer 的参考资料，先提取可量化的风格指纹，再判别"类型公约数"与"作者指纹"，最后产出一个带量化节奏指标的文风预设。全程只用文件工具完成，不需要改任何代码或配置。

## 原理：为什么不能直接仿写

```
直接仿写：1 篇源文 → 抽特征 → 换皮 → 该作者的口头禅、专属桥段一起学进来 → 四不像
熔铸：    N 篇同类源文 → 指纹互消 → 只剩类型共性 → 提炼出可迁移的写法
```

多个作者共有的特征属于"类型本身"，可以学；只有个别作者独有的特征是"作者指纹"，学了就会在正文里复刻出别人的影子。单篇输入时没有互消基准，必须退化为显式的指纹剥离（见第 5 步）。

## 目标层判定

writer 的 references/styles 存在于两个可写层，由当前会话形态自动决定，不询问用户：

| 会话形态 | 判定方法 | references 来源 | styles 产出 |
| --- | --- | --- | --- |
| 项目会话 | cwd 下存在 `manuscript/` 或 `agents/writer/` | `agents/writer/references/` | `agents/writer/styles/` |
| 用户资产会话 | 上述标志不存在（cwd 是运行时 Workspace Root） | `.nbook/agents/writer/references/` | `.nbook/agents/writer/styles/` |

两层差异要在汇报里讲清：项目级只对当前书可见可编辑；用户资产级跨所有书共享，但从项目 UI 里不可编辑、不可删除，后续管理走文件系统。

系统内置种子层 `assets/workspace/.nbook/agent/profiles/builtin/writer.home/` 永远只读，禁止写入。

## 工作流

### 1. 解析引用

- 用户明确引用了哪些资料，就处理哪些；一篇或多篇都可以。
- 多篇（≥2）引用时走完整熔铸流程（第 3-4 步），融合成**一个**混合 style。
- 单篇引用时走指纹剥离流程（第 5 步），并在汇报中说明单源局限：无法互消，只能显式剥离。
- 用户没指明文件时，列出当前层 references 目录内容（文件名 + frontmatter 里的 label），让用户选，不要擅自全量处理。
- 引用的文件不存在时停下来说明，不要凭空生成。

### 2. 规范化元数据

- 文件带完整 frontmatter（`key/label/sourceTitle/sourceChapters/generatedFrom`）→ 直接使用。
- 裸文件（纯正文没有 frontmatter）→ 在内存中派生元数据，**不写回原文件**：
  - `key`：文件名去扩展名；若含不安全字符（非 `A-Za-z0-9._-`）则自拟一个语义化英文 kebab-case 名并在汇报中说明对应关系。
  - `label`：文件名或正文首行标题。
  - `sourceTitle`：同 label；`sourceChapters`：`未标注`；`generatedFrom`：实际文件路径。

### 3. 指纹提取（每篇必做）

通读源文，逐篇提取以下四类指纹。所有数字必须实测，禁止编造：

**表层节奏指纹**
- 句子总数（按 。！？ 切分）、感叹号密度（！/句）、逗号密度（，/句）
- 对话密度：带引号或对话标记的段落占比
- 段落：平均字数、最长段字数、短段（<30 字）的使用位置规律
- 分节方式：章节标题 / 裸数字 / 空行 / 无分节

**句式指纹**
- 抽 3 个代表性段落，检查：相邻句结构是否重复、长短句如何交错、复句比例大概多少
- 人称（第一/第三）与视角贴身程度
- 思维标记计数：「心想 / 意识到 / 感到 / 觉得 / 认为 / 明白」出现次数

**词汇指纹**
- 高频特征词：出现 ≥5 次的非通用词（动词、形容词、语气词、口头禅）
- 标志性比喻或意象：同一比喻是否反复出现

**结构指纹**
- 开篇 30 行的钩子类型（悬念 / 动作 / 对话 / 设定轰炸 / 生活细节）
- 场景推进链条（如"日常动作 → 异常侵入 → 反应 → 推进"）
- 人物命名风格（姓名长度、年代感、绰号使用）
- 情绪处理模式（直陈 / 动作外化 / 环境映射）

### 4. 公约数判定（多篇熔铸核心）

把各篇指纹逐维对照，按下表机械判定：

| 该特征出现的篇数 | 判定 | 处理 |
| --- | --- | --- |
| 过半（如 5 篇中 ≥3，2 篇中 =2） | 类型公约数 | 提炼进 style，作为该维度的主干取值 |
| 仅 1 篇 | 作者指纹 | 剔除，不进 style；若是情节元素列入禁区 |
| 其余情形 | 存疑 | 在汇报中列出，让用户裁决后再写文件 |

再按"风格级 vs 内容级"二次过滤：

- **风格级元素**（句式、节奏、视角、对话规则、情绪处理、场景推进）→ 学公约数，这是 style 的本体。
- **内容级元素**（人名、地名、道具、组织、桥段、死亡方式、金手指形态）→ 一律不复刻。正确/错误示例和典型例文中出现的必须是改写自创的内容。
- **宁可远，不可近**：犹豫某个示例是否太像某篇源文 → 直接换掉。

### 5. 作者指纹剥离（单篇退化流程）

单篇没有互消基准，改为显式剥离，产出两部分：

- **可迁移技法层**：节奏、句式、视角、推进链等写法层面的特征 → 正常进 style 各维度。
- **作者专属层**：口头禅、标志性比喻、独特道具、专有名词体系、高频套话 → 全部写进 `[核心禁区]`，标注"源文作者专属，禁止复刻"。

### 6. 风格解剖（维度框架）

基于指纹结果撰写以下维度。前 13 个是核心维度，原则上不可缺；其余按目标风格特征增删：

- 文体定位（H1 标题：`# 文体定位：<风格名> · <一句话定位>`）
- [核心理念]
- [叙事视角]
- [场景推进规则]
- [段落结构]
- [角色表现工具箱]（编号子工具，每个配正确/错误示例）
- [语言与句法]
- [对话规则]
- [情绪处理]
- [设定呈现]
- [量化节奏指标]（见第 7 步）
- [原文风格锚点]
- [核心禁区]
- [生成时的自检顺序]
- [典型例文]

结构范本：`assets/workspace/.nbook/agent/profiles/builtin/writer.home/styles/reborn-villain-loli-magic-girl.first-three-chapters.style.md`。写之前先读它，对齐颗粒度与格式。

每个含规则的维度都要有一组「正确示例 / 错误示例」，错误示例要写成典型的失败样子，不是简单否定正确示例。

### 7. 量化节奏指标

把第 3 步的实测指纹换算成写作时可执行的目标值，格式示例：

```
[量化节奏指标]
  - 感叹号：约 0.15 个/句（源文实测区间 0.12–0.18）
  - 逗号：约 1.2 个/句
  - 段落：平均 60–90 字，禁止超过 200 字的段落
  - 对话：每 100 字至少 1.5 处对话标记
  - 句式：相邻 3 句结构不重复；每段同时含 ≤10 字短句与 ≥30 字长句
  - 思维标记：整章 ≤5 处，优先用动作和台词外化心理
```

规则：所有数字来自源文实测并给出区间；源文没有的特征不要编造指标；多源融合时取公约数篇的实测区间。

### 8. 反 AI 味基线

以下禁用项默认写入 `[核心禁区]`，与内置 llmlint 技能口径一致（写作后可用 llmlint 复查）：

- **禁用模板描写**：眼中闪过 / 眼底闪过 / 嘴角勾起 / 眼眶微红 / 咬了咬唇 / 身子一颤 / 心头一紧 / 倒吸一口凉气 / 目光一凝 / 瞳孔一缩 / 不可置信 / 冷冷地说
- **禁用句式**：对X而言 / 一切都在 / 一种说不出的 / 真正的X是Y / X的意义在于 / X既是Y也是Z / 谁说X就一定Y
- **思维标记**（心想 / 意识到 / 感到 / 觉得 / 认为 / 明白）高密度使用是强 AI 特征，默认限制频率并用动作外化替代

例外规则：若源文本身高频依赖其中某项（那属于它的风格），跟随源文保留，并在该条目后标注「源文特征，按源文执行」。

### 9. 写出 style 文件

路径：`<目标层>/styles/<key>.style.md`。frontmatter 合同（字段名、类型必须完全一致）：

```yaml
---
key: "<单篇时 = 参考 key + .style；融合时自拟语义化 kebab-case 名>"
label: "<中文风格短名>"
sourcePreset: "<来源 reference 的 label；多篇用「A / B」并列>"
identifier: "<uuid v4，用 bun -e \"console.log(crypto.randomUUID())\" 生成>"
name: "📝文风（选一）|<label>"
enabled: false
role: system
---
```

正文用 `<Writing_style>` 开闭标签包裹，内部按第 6 步的维度框架组织。篇幅对齐范本量级（约 200 行），不为凑维度注水。

`key` 与目标层已有 styles 冲突时，在末尾追加 `-2` 等序号并在汇报中说明。

### 10. 示例纪律

- 正确/错误示例和典型例文必须**基于原文改写**：换角色名、换事件、保留语感与节奏，不复刻任何角色名、专有设定、章节事件或完整桥段。
- 除 `[原文风格锚点]` 允许引用不超过 10 字的短语级原文（并注明用途）外，其余位置与源文不得出现连续超长相同片段。
- 典型例文是用该风格新写的原创段落，不是原文摘抄；写完对照 `[量化节奏指标]` 自查一遍。

### 11. 自检清单

写出文件后逐项核对，有问题就改完再汇报：

1. frontmatter 七字段齐全，`enabled` 是布尔 `false`，`role` 是字符串 `system`。
2. `<Writing_style>` 开闭标签完整。
3. 核心维度无缺项；确实不适用的维度写明「本风格不适用，因为……」，不留空白。
4. 含规则的维度都有正确/错误示例组。
5. `[量化节奏指标]` 每个数字都能追溯到源文实测，无凭空编造。
6. 多源时：公约数/作者指纹的判定过程在汇报中有对照摘要；单源时：作者专属层已全部进入 `[核心禁区]`。
7. 反 AI 味基线已写入 `[核心禁区]`（或有明确的「源文特征」例外标注）。
8. 无长串照抄；锚点均为短语级。
9. `key` 无冲突。

## 汇报

完成后告知用户：

- 生成的文件路径和 `label`。
- 熔铸摘要：提取了几类公约数、剔除了哪些作者指纹（单源时列剥离清单）。
- 如何启用：打开 writer 设置 → 文风下拉选择该预设（新生成的预设默认未启用，不会影响当前写作）。
- 若产出在用户资产层：提醒该文风已跨书共享，但项目 UI 内只读，改名删除需到文件系统操作。

## 边界

- 不修改 references 下任何文件（包括补 frontmatter）。
- 不自动切换 writer 当前使用的文风，不把 `enabled` 改成 true。
- 不写入 manuscript/，不触碰系统内置种子层。
- 单次只服务用户引用的资料，不做全目录批量生成。
